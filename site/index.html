30 October 2026Lab finding

483 requests. 483 extra entries.

A clean Windows 10 test reproduced the buildup: one extra internal tracking entry for every request for controller state.

We reconnected the controller and verified that the list started empty. Our test program made 483 requests. All 483 initially had to wait, all later completed successfully, and the driver ended with 483 entries. None carried the test program’s ID in the field used to find and reuse them.

We saw no identical replies back to back after excluding their update number. This run reproduced the tracking problem without reproducing the suspected stream of unchanged replies.

In a separate run, 355 requests added 355 entries. Those entries were still there after the test program exited.

What comes next

Repeat the clean test with the missing ID initialized correctly. That new comparison is prepared but hasn’t run. Earlier debugger experiments showed reuse after the correction; an in-game FPS benefit remains unproven.

30 October 2026What we learned

Untouched doesn’t always mean unchanged.

Our debugger kept seeing controller activity even when nobody touched it. We now have a concrete clue: small variations in the stick readings before they reach Windows.

In one recording, the resting stick sat near the edge of its configured dead zone. Small changes took it across that edge, and Windows reported the corresponding jump. The sampled readings matched the expected conversion whenever the raw snapshots stayed stable across a check.

That helps explain activity from an untouched controller in this setup. The separate Windows tracking bug still matters: legitimate input changes can keep adding entries when they should be reused.

29 October 2026Lab finding

A small missing detail. A growing pile of extra work.

We can now reproduce a specific controller-driver problem in a Windows 10 test machine — and show that correcting one missing value changes its behavior.

Behind the scenes, Windows creates places for controller updates to wait. In the driver we tested, a missing detail means it keeps creating new ones for the same program instead of reusing the one it already has. That growing pile can make controller checks more expensive.

In earlier lab comparisons, correcting the missing value stopped that buildup and made some controller checks much quicker. Basic held-button, stick and vibration checks also worked with the correction.

The important bit

This is a temporary debugger experiment, not a fix you can download. It was tested with a PS3 controller through DsHidMini on one Windows 10 setup. We still need to show a benefit inside a real game and check controller behavior more thoroughly.

Our test machine also has an older GameInput revision than the reporting player’s machine. The matching driver gives us a useful lead, but it doesn’t make every part of the setup identical.

29 October 2026What we learned

Leaving the controller alone didn’t tell the whole story.

A fresh comparison with the controller left untouched showed little timing difference. That matters: the problem doesn’t mean every controller check is automatically slow.

After a 30-second moving-stick test, the uncorrected setup had accumulated thousands of internal entries. Checks for controller slots with nothing connected became roughly four to ten times more expensive than in the earlier idle test. That is a controller-call measurement, not an FPS multiplier.

Stopping GameInput Service afterward stopped the programs producing those entries, but left the accumulated entries and the extra cost behind. Restarting the service didn’t clear them either.

We haven’t run that exact continuous-movement test on a fresh corrected setup yet. It’s another useful clue, not a complete comparison or a reason to start changing services on your own PC.

28 October 2026From the community

A Left 4 Dead 2 report gave us a better trail to follow.

A player reported a large FPS drop and heavy stutter with GameInput Service enabled and a controller connected. Follow-up recordings compared the service off and on during the same Windows session, with the game still running.

When the player reported the stutter, the game was spending much more of its sampled time checking controllers and cleaning up after those checks. With the service disabled, that expensive path was much less prominent.

Those recordings helped us focus the investigation. They did not independently measure the reported FPS numbers, prove the driver caused that player’s entire problem, or establish a universal fix.

25 October 2026Starting the investigationUpdated 29 October

First, check whether the obvious explanation holds up.

One early idea was that GameInput might keep asking for the same controller state as fast as possible. Our Xbox-controller tests over USB and Bluetooth didn’t reproduce that suspected behavior. The tested requests waited for input updates.

That didn’t make the player reports go away. It told us to keep looking instead of treating an early theory as a confirmed cause. Repeated “rumble off” traffic was also an assumption, not something the original recording established.

We made the diagnostic tools easier to use and asked for reports captured while the problem was actually happening. The Windows 10 queue problem described above is a later, more specific finding.

Findings, including corrected assumptions ↗

Before you change anything

The short version

  • There is a real driver defect in the Windows 10 version we tested.
  • We don’t know whether it explains every report of controller-related stutter.
  • There is no supported one-click fix to install from this project.

Quick answers

You might be wondering…

Is my controller affected?

We can’t tell from the model alone. Windows version, driver, connection and game all matter. Describe what happens and we’ll help you work out what to collect.

Should I disable GameInput?

Keep your original settings for the first report. Some games need GameInput. Talk to us before changing services so we can help you test without losing useful evidence.

Does this also affect Windows 11?

The Windows 11 driver we checked from the January 2024 update for 22H2/23H2 initializes the ID correctly. Other Windows 11 stutter reports may have different causes; this finding doesn’t settle those reports.

Has Windows 10 received a fix?

The October 26, 2026 Windows 10 package we inspected still contains the affected driver. We haven’t identified a shipping Windows 10 correction for this fault. Verified versions and limits.

Can I help without coding?

Yes. A clear description and a short recording while the stutter happens can be very useful. Our collector uses tools already included in Windows.
